# 方法规格

本文逐项给出 `configs/recipe.json` 中每个字段的语义与取值依据。

---

## 1. 任务与指标

| 项 | 值 |
|---|---|
| 输入 | 一段英文文本，40–250 词 |
| 输出 | 18 个模型标签之一 |
| 类别空间 | OpenAI 5、Google 4、Anthropic 5、Qwen 1、ZAI 2、Moonshot 1 |
| 指标 | balanced accuracy（各类召回率的算术平均） |
| 训练集 | 2,699 条 / 150 个提示词，每提示词约 18 条 |
| 测试集 | ≈4,000 条，**提示词与训练集完全不重叠** |

指标选择决定了后面两件事：类别先验必须被压平（Sinkhorn），以及不能只看总体准确率（必须逐类看召回）。

---

## 2. 数据流

```
train.csv ──┬─→ 主干成员（截断 LM + LoRA 适配器）──→ logits × w
            ├─→ 冻结编码器头 ──────────────────→ logits × w
            ├─→ 外部匹配语料池（同分布扩充）────→ SVC / 组头
            └─→ 互补堆叠（独立进程）────────────→ comp_logit.npy × 0.15
                                                      │
test.csv  ────────────────────────────────────────────┴─→ 融合 → 后处理 → 标签
```

关键点：

- **词表、标准化、分类器只在 train 上拟合**；冻结编码器可以对 train+test 一起前向（无标签，不构成泄漏）。
- **外部语料池**用于扩充稀有类，权重 0.5（`extra_w`），并带样本权重衰减（见 §4.3）。
- **组（group）**：测试集的提示词未知，需从文本聚类恢复，供中心化与簇匹配使用。聚类用词级 TF-IDF + 停用词 + SVD + 平均连接，阈值 0.60，簇规模 2–18。

## 3. 主干成员（6 个）

| # | name | 基座 | 适配器 | 截断层 | pool 层 | w | bs | max_len | 备注 |
|---|---|---|---|---|---|---|---|---|---|
| 1 | `q14v5` | Qwen3-14B-Base | 5 折 + 全量（v5） | 27 | 2,4,6,8,12,16,20,24 | **3.0** | 8 | 384 | twin 0.35，gauss 0.70 |
| 2 | `q8v5` | Qwen3-8B-Base | 5 折 + 全量（v5） | 24 | 同上 | **2.0** | 16 | 384 | twin 0.35，gauss 0.44 |
| 3 | `ll8v5` | Llama-3.1-8B | 5 折 + 全量（v5） | 24 | 同上 | **1.0** | 16 | 384 | twin 0.35 |
| 4 | `n14b` | Qwen3-14B | 二阶段 LoRA | 配置驱动 | 配置驱动 | **2.5** | 8 | 配置 | `no_final_norm`，带 `eos_id` |
| 5 | `q25_14` | Qwen2.5-14B | 二阶段 LoRA | 配置驱动 | 配置驱动 | **1.0** | 8 | 配置 | 同上 |
| 6 | `deb` | DeBERTa-v3-large | 冻结 | — | — | **1.0** | — | — | 编码器路径 |

### 3.1 为什么是"截断主干 + 轮换适配器"

七个 8B–14B 模型同时驻留显存是不可能的。实际做法是：

- 主干只保留前 N 层（14B 留 27 层、8B 留 24 层），丢掉 LM head；
- 每个适配器（LoRA）体积极小，轮流换入；
- **一次前向同时产出三种读数**：普通 pooled 特征、按组中心化后的特征（twin）、族内门控读数。

这样同一份算力产出三倍成员。加载时出现的 `UNEXPECTED`（未被用到的上层与 LM head）是预期行为，不代表成员失败。

### 3.2 中心化 twin（adaptive centering）

同一条提示词下，18 个模型的输出共享话题，风格差异被话题方差淹没。做法是按组减去组均值再分类：

```
X_centered[g] = X[g] − mean(X[g])        # g 为同一提示词的样本组
P_twin = LR(X_centered)                  # 单独拟合一个分类器
```

- 只对**簇规模 ≥ 2** 的行生效，其余置 0（`adapt_thr = 0.15` 控制生效门槛）；
- twin 权重 `adapt_w = 1.0`，再乘以该成员自身权重；
- 三个 v5 成员的 twin 系数为 0.35，二阶段成员另有系数。

这是本方案里"用结构换精度"的典型：不需要更多参数，只需要知道哪些文本属于同一组。

### 3.3 共享提示词高斯组头

在四个测量视图上各拟合一个高斯组头（`gauss.*`），用 WPCA 降到 384 维、Ledoit-Wolf 收缩估计协方差、精确边缘化 3 个样本、EM 迭代 5 轮：

| 头 | 源视图 | 降维 | T1 | Tg | 权重 |
|---|---|---|---|---|---|
| `gauss_q3_8b_L22` | q3_8b L22 mean | 384 | 2.351 | 2.306 | 0.329 |
| `gauss_glm9b_L8` | glm9b L8 mean | 384 | 2.722 | 2.596 | 0.165 |
| `gauss_q3_4b_L4` | q3_4b L4 mean | 384 | 2.725 | 2.578 | 0.125 |
| `gauss_debv3l_L24` | debv3l L24 mean | 384 | 3.112 | 3.069 | 0.250 |

收缩设置：`se_shrink=lw`、`sp_shrink=lw`、`lam_floor=1e-4`、`n_exact=3`、`inj=True`、`repel=True`。

## 4. 互补堆叠（16 个成员）

独立进程产出 `comp_logit.npy`，再以 **0.15** 的权重并入。其内部按 **log 概率乘数**加权：成员乘数合计 **2.86**，另有中心化 twin 乘数 1.38（§4.1）。

| 成员 | 权重 | 说明 |
|---|---|---|
| `stylegram` | **1.516** | 词/字符 n-gram 四视图 + LinearSVC；唯一的大权重词法成员 |
| `tokattn_deb` | 0.185 | DeBERTa token-attention 头 |
| `lora24_public` | 0.177 | Qwen3-8B LoRA 检查点（public 版） |
| `lora24_claude` | 0.177 | 同上（claude 专精版） |
| `lora20_q25_instyle` | 0.170 | Qwen2.5-7B in-style LoRA（保留 20 层，名字里的 20 指层数） |
| `tokattn_q35` | 0.153 | Qwen3.5-9B token-attention；**最贵的成员**（1.7–2.7 h） |
| `desk` | 0.132 | desklib 检测器编码器头 |
| `lora24_seed7` | 0.113 | 同 public 版，不同种子 |
| `ultrabert` | 0.095 | UltraBERT-380M，5 折平均 |
| `stylometry_lgb` | 0.063 | 手工风格计量 + LightGBM |
| `debv3l` | 0.050 | DeBERTa-v3-large 头 |
| `electl` | 0.032 | ELECTRA-large 头 |
| `q3_8b` / `q25_7b` / `q3_4b` / `glm9b` | **0.0** | 普通头权重为 0，**只用它们的 twin** |

### 4.1 普通头为 0、twin 为正

四个 LM 的普通 pooled 头在融合中最优权重是 0——说明它们的信息已被更强的成员覆盖。但它们的**中心化 twin** 权重分别为 0.329 / 0.212 / 0.125 / 0.165。

这个现象本身是一个结论：**同样特征，去掉了组均值之后才有增量**。

### 4.2 族内门控

| 门控 | λ |
|---|---|
| claude_style | 1.5 |
| claude_lora | 1.0 |
| family | 0.25 |

只在"已判为该族"的行上做族内重判，把 5 类问题降成族内 5 分类。外部扩充样本在门控训练时权重降为 0.25。

### 4.3 外部样本权重

```
若某类在池中标签数 ≥ 12：
    该类原始样本保留 (1 − 0.5) 的类权重
    该类外部样本分享 0.5 的类权重
```

避免扩充样本把原始分布冲淡。

## 5. 融合

```
P = softmax( Σ_members  w_m · logit_m  /  Σ w_m )
```

主融合的权重账（成员之外另有两项）：

| 项 | 权重 | 说明 |
|---|---|---|
| 六个主干成员 | 3.0 / 2.0 / 1.0 / 2.5 / 1.0 / 1.0 | 见 §3 |
| 4 视图 n-gram SVC | **1.5** | 只吃词法信号，独立于互补堆叠里的 `stylegram` |
| 外部匹配语料池 | **0.5** | 影响 SVC 与组头的训练样本权重 |
| 中心化 twin | 1.0（再乘成员权重） | 见 §3.2 |
| `tfidf_w` / `distort_w` | **0** | 早期版本使用，本配方关闭 |

工程上先对每个成员做 `log_softmax` 再乘权重求和，最后除以权重和。在 log 域加权，避免概率连乘时被单个成员主导。

## 6. 后处理（三处）

### 6.1 排版硬约束（guards）

对每条文本，若出现某标点，且当前 argmax 不在该标点的允许集合内，则把不允许的列置 `-1e9`。

```python
for mark, allowed in GUARDS:
    forbidden = [label not in allowed for label in LABELS]
    if mark in text and argmax(logits) not in allowed:
        logits[forbidden] = -1e9
```

五条规则见根目录 README。语义是**单项蕴含**：出现 → 必定属于该集合。反向不成立（属于该集合不意味着一定出现）。

### 6.2 Sinkhorn 边缘平衡

```python
Q = P.copy()
for _ in range(100):
    Q *= (len(Q) / n_classes) / Q.sum(axis=0, keepdims=True)   # 列压平
    Q /= Q.sum(axis=1, keepdims=True)                          # 行归一
logits = (1 - λ) * log(P) + λ * log(Q)      # λ = 1.0
```

只在 `len(test) ≥ 18` 时启用。作用是把 18 类的预测频次压向均匀，直接对应 balanced accuracy 的口径。

### 6.3 稠密簇匈牙利匹配

对规模在 **12–18** 之间的簇，做一次一对一分配（`scipy.optimize.linear_sum_assignment`），强制同簇内不重复：

```python
for g in clusters where 12 <= size(g) <= 18:
    rows, cols = linear_sum_assignment(-logits[g])
    logits[g] = -1e9
    logits[g[rows], cols] = 0.0
```

阈值 12 是保守选择：簇越小，"每组恰好含每个模型"的假设越不可靠。

### 6.4 ATLAS 门控

只在 **top-2 margin < 0.3** 的行上调用 ATLAS（source-conditioned likelihood），权重 0.10：

```python
margin = sorted(P)[:, -1] - sorted(P)[:, -2]
rows = where(margin < 0.3)
P[rows] = P[rows] - 0.10 * P[rows] + 0.10 * ATLAS[rows]
```

按 token 数从短到长打分，带 token 比例时间投影；若投影会超出预算则抛异常并回退（ATLAS 整体跳过，其余成员照常出分）。

## 7. 运行时与降级

| 项 | 值 |
|---|---|
| 硬件 | 免费 T4 × 2 |
| 断网 | 是 |
| 实测 | **4 h 4 min**（含互补堆叠与 ATLAS） |
| 时间预算 | `8.3 h − comp 耗时 − 600 s` 留给 ATLAS |
| 关键开销 | 约 40 GB 模型加载 |

**降级顺序**（时间不够时按此砍）：

1. `NTL_DROP_Q35=1` —— 去掉 `tokattn_q35`，省 1.7–2.7 h；该项乘数 0.153，占全体（含 twin 共 4.24）约 3.6%
2. 关闭 ATLAS（`atlas_w=0`）—— 只影响低 margin 行
3. 关闭互补堆叠（`comp_w=0`）—— 损失最大的单步，不建议

**注意**：`load_trunk` 只在检测到多卡时做显存切分，单卡会让 14B 走 CPU。**分到的 GPU 数量比任何调参都更影响能否跑完。**

## 8. 自检

推理过程中内置三处断言，用来区分"跑完了"和"跑对了"：

| 检查 | 期望 |
|---|---|
| 每个 l24 成员 | 训练行 in-sample 准确率 > 0.5，否则该成员未被正确加载 |
| 每个 head 成员 | 同上 |
| ATLAS 输出 | 行和为 1（`atol=1e-4`）、全为有限值 |
| 互补堆叠 | `comp_meta.json` 的 id 顺序与 test 完全一致 |
| 提交文件 | id 唯一、无空值、标签在 18 类内 |

日志里出现 `COMP SKIPPED` / `ATLAS SKIPPED` / traceback，或缺少任一必需适配器，都说明成分不完整——此时"跑完"不等于"复现"。

## 9. 已知失效条件

| 条件 | 后果 | 应对 |
|---|---|---|
| 测试集不是"每组多个模型"结构 | Sinkhorn 与簇匹配反向伤害 | 关闭二者（`--no-balance --no-cluster`） |
| 模型版本更新 | 排版规则失效 | 重新统计五条规则的支持集 |
| 单条判定 | 0.651 不足以支撑个体结论 | 只在语料库层面做统计，不做个案认定 |
| 领域漂移（非竞赛分布的文本） | 误判率显著高于验证集 | 逐类标定误判率，勿用一个平均数代替 |
