# LLM Attribution Stack

**18 类大模型文本溯源（authorship attribution）：分层集成方法与后处理规则**

给定一段 40–250 词的英文段落，判断它由 18 个前沿模型中的哪一个生成。这是一个**作者归属**问题，而非"是否为 AI 生成"的二分类。

本仓库是一份**方法规格 + 后处理参考实现**：把一套达到 balanced accuracy **0.651** 的方案拆成可读、可核对、可移植的形式，去掉与竞赛平台绑定的工程细节，只保留决定结果的算法结构。

---

## 为什么值得拆开看

这类任务的上限不在单个模型，而在**信息源的正交程度**与**后处理对结构先验的利用**。

本方案的两个关键判断：

1. **一个主干榨出多个成员**。不是加载六个模型，而是一个截断主干 + 轮换 LoRA adapter；每次前向同时产出普通读数、中心化读数（twin）与族内读数。同样算力下成员数翻倍。
2. **排版指纹是可以写成硬规则的**。五种标点符号在训练集里呈现严格的分层分布，可以当作**单项蕴含**使用——只要违反了，就直接禁止对应类别。这不是调参，是把已知事实写进解码器。

第 2 点是本方案最容易复现、也最容易被忽略的部分：五条规则覆盖了相当一部分高置信度错误，且**完全可解释**。

## 方法概览

```
                    输入文本
                        │
        ┌───────────────┴───────────────┐
        │                               │
   主干成员（GPU）                  互补堆叠（CPU/GPU 混合）
   6 个成员，权重 3/2/1/2.5/1/1      14 个成员，加权 0.15
        │                               │
        └───────────────┬───────────────┘
                        │
              加权 logit 融合
                        │
         ┌──────────────┴──────────────┐
         │   ① ATLAS 门控（margin<0.3） │  权重 0.10
         │   ② Sinkhorn 边缘平衡        │  100 轮
         │   ③ 排版硬约束 + 稠密簇匹配   │
         └──────────────┬──────────────┘
                        │
                    18 类标签
```

| 层 | 成员 | 权重 | 说明 |
|---|---|---|---|
| 主干 | Qwen3-14B-Base + 5 折 LoRA + 全量适配 | **3.0** | 截断至 27 层，max_len 384 |
| 主干 | Qwen3-8B-Base + 5 折 LoRA + 全量适配 | **2.0** | 截断至 24 层 |
| 主干 | Llama-3.1-8B + 5 折 LoRA + 全量适配 | **1.0** | 截断至 24 层 |
| 主干 | Qwen3-14B + 二阶段 LoRA（另一套检查点） | **2.5** | no_final_norm |
| 主干 | Qwen2.5-14B + LoRA | **1.0** | no_final_norm |
| 主干 | DeBERTa-v3-large 编码器头 | **1.0** | 冻结主干 |
| 互补 | 词/字符 n-gram 四视图 SVC | 1.5（内部） | 只吃词法信号 |
| 互补 | 手工风格计量 + LightGBM | 0.063 | 内部权重 |
| 互补 | UltraBERT 380M × 5 折 | 0.095 | 内部权重 |
| 互补 | LoRA 检查点四个 | 0.113–0.177 | 内部权重 |
| 互补 | token-attention 头两个 | 0.153 / 0.185 | 内部权重 |
| 互补 | 编码器头（DeBERTa / ELECTRA / desklib） | 0.032–0.132 | 内部权重 |
| 门控 | ATLAS（source-conditioned likelihood） | 0.10 | 仅 top-2 margin < 0.3 的行 |

## 三处后处理，贡献了主要增量

| 处理 | 做什么 | 为什么有效 |
|---|---|---|
| **排版硬约束** | 5 条规则：出现某标点即禁止若干类别（`-1e9`） | 训练集里这些符号的分布是**严格分层**的，违反即可排除 |
| **Sinkhorn 边缘平衡** | 100 轮行列归一，把预测分布压向均匀 | 指标是 balanced accuracy，对类别先验敏感 |
| **稠密簇匈牙利匹配** | 对规模 12–18 的簇做一对一分配 | 同题段落不应重复预测同一模型 |

五条排版规则（字符 → 允许的模型集合）：

| 字符 | 含义 | 允许出现的模型 |
|---|---|---|
| `' — '` | 前后带空格的 em dash | claude-opus-4-6, claude-opus-5, glm-5.3, glm-5.3-flash |
| `'’'` | 弯单引号 | 全部 gpt / gemini / qwen3.8-max / kimi-k3（即除 claude、glm 外） |
| `'"'` | 直双引号 | 全部 claude、全部 gemini、全部 glm、gpt-5.5、kimi-k3 |
| `'“'` | 弯双引号 | gemini-3.8-flash、gpt-5.5、gpt-5.6 三兄弟、gpt-6-astra、kimi-k3、qwen3.8-max |
| `'–'` | en dash | claude-opus-5、gemini-3.1-pro-preview、glm-5.3-flash、gpt-5.6 三兄弟、kimi-k3 |

这些规则在 38k 条匹配语料上**零违反**——不是拟合出来的阈值，是数据本身的结构。

## 仓库结构

```
llm-attribution-stack/
├── README.md               # 本文件
├── docs/METHOD.md          # 完整方法规格：逐成员参数、后处理语义、预算与降级
├── configs/recipe.json     # 机器可读的完整配方（全部权重与超参）
├── src/postprocess.py      # 后处理参考实现（可独立运行，仅依赖 numpy/scipy）
└── NOTICE                  # 第三方来源与许可
```

`src/postprocess.py` 是可以直接跑的最小核心：给一份 logit 矩阵、原文和簇编号，它完成排版约束 → Sinkhorn → 稠密簇匹配 → 输出标签。

```bash
pip install -r requirements.txt
python -m src.postprocess            # 用合成数据跑一遍，验证逻辑
```

## 适用范围与已知边界

- **单条精度不足以做个体判定**。18 类 balanced accuracy 0.651 意味着约三分之一会错；用于"缩小候选范围"或"语料库层面的统计审计"是合适的，用于"认定某一段的作者"不合适。
- **Sinkhorn 与簇匹配依赖"测试集每组含多个模型"的结构假设**。在任意真实文本上该假设可能不成立，此时应关闭这两步（`--no-balance --no-cluster`）。
- **排版规则是从该 18 模型在特定提示词分布下的输出中统计得到的**，模型版本更新后可能失效，需重新统计。
- 本仓库不含模型权重与数据；主干推理需要对应基座模型与适配器。
